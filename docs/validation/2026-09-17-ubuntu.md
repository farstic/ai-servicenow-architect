## S-17 on Linux — attempted, and it stops at a dialog

ARC-04-S04 criterion 7 — *"under Claude Code, an unconfigured server shows `✔ connected` in `/mcp`
and no error"* — is CONFIRMED on macOS (2026-09-07, 2.1.258) and carried **NOT RUN** for a second
OS. It is still NOT RUN, and this is exactly where it stops.

**The design-only half reproduces on Linux, and that much is new evidence.** `claude mcp get
servicenow` reports, without any interactive session:

```
Scope: Project config (shared via .mcp.json)
Status: ✘ Rejected (see disabledMcpjsonServers in settings)
Type: stdio · Command: node · Args: ${CLAUDE_PROJECT_DIR:-.}/packages/snowarch/dist/server.js
```

That is Sitting A's C3 observation, independently produced on a second OS by a different tool than
the one the doctor uses — E-27's *"project entry present, disabled in design mode"* is true here too.

**The unconfigured-and-ENABLED half cannot be reached headlessly.** S-17 needs the server enabled
with no instance configured, and two documented settings were tried, in this order:

| What was tried | Resulting `Status` |
|---|---|
| remove `servicenow` from `disabledMcpjsonServers` | `⏸ Pending approval (run `claude` to approve)` |
| add `enabledMcpjsonServers: ["servicenow"]` | `⏸ Pending approval (run `claude` to approve)` — unchanged |

A project server declared in `.mcp.json` waits for an **interactive approval**, and `multipass exec`
cannot drive a TUI dialog. The instance store was absent throughout (``.local/instances.json`` never
created), so the *unconfigured* precondition was genuinely met — only the approval was not.

**What was deliberately NOT done.** The approval flag could be written into `~/.claude.json` by hand
until the panel turned green. That would measure a state this observer forged rather than one Claude
Code granted, and a `CONFIRMED` obtained that way would be worth less than a `NOT RUN` — so the row
stays NOT RUN and names the gate. It needs one interactive Linux session, which belongs to Sitting C
or D.

**One finding that makes the next attempt cheaper:** `claude mcp list` prints a live status column
(`✔ Connected` for the remote servers on this machine), so the `/mcp` panel may not be the only way
to answer S-17's first half. Worth trying before booking an interactive sitting for it.

## Observer notes

Everything the reader had to guess, look up elsewhere, or work around — including the merely ugly.

- **Path A installs the wrong thing during a release candidate.** The page's one-line command clones
  the default branch, and `main` is at `16fe2df` (2026-09-12) while the candidate is `e6f5b59`. A
  reader following the page today gets a tree five days and roughly twenty merged pull requests
  behind the thing being validated. The page is right for a released product and has no step for a
  candidate; the deviation is in the timeline above rather than hidden.
- **The page's preflight count is wrong in both directions.** `docs/INSTALL.md:49` says *"Six
  preflight checks print a line each (git, Claude Code, disk, network, Node, platform)"* and names
  six. The **Node path prints seven** — the first is `root`, which the sentence omits — and the
  **Node-free path prints five** (`root` and `platform` are not among them). So the number is right
  for neither path a reader can be on. Not Linux-specific: a macOS bootstrap log shows the same
  seven. Raised as `ARC-06-C11`.
- **`git describe` in a fresh clone names an import tag.** Before the checkout it answered
  `import/engine-v2.8.0-worktree-476-g16fe2df`. Only ugly — nothing depends on it here — but it is
  what a reader sees if they check what they have.
- **One line in B02 is not in the page's sample run:** `[docs] sparse init --cone (pattern-mode
  config found)`. The corpus arrived correct and complete; the sample simply does not show it.
- **The workspace was never trusted, and it says so every time.** Every headless session printed
  `Ignoring 236 permissions.allow entries from .claude/settings.json: this workspace has not been
  trusted.` That is correct behaviour and the same 236 rules Sitting A's trust dialog read aloud —
  but it means **no observation in this record depends on the allow-list**, which is worth knowing
  when comparing it with a trusted-session record.
- **The untrusted workspace silently changes what two tests can see.** Both `/snowarch status` and
  `/snowarch setup-instance` had their `./snowarch doctor …` Bash call **denied** — one
  `permission_denials` entry each — because the 236 allow entries are ignored in an untrusted
  workspace. **Both skills produced correct output anyway**, from the cached doctor report and from
  files they could read. That is a good result and it is also a gap: the S-16 allow-rule behaviour
  Sitting A confirmed on macOS has no Linux counterpart in this record. *(A second possibility I
  cannot rule out from here: the denied command was a compound — `./snowarch doctor --quick --json
  2>&1; echo "EXIT:$?"` — and a `Bash(./snowarch:*)` grant may not match a command containing `;`.
  Either way the observation stands; the cause does not, and I am not going to guess between them.)*

- **Two harness artefacts of this observer's own making**, recorded so they are not read as product
  behaviour: `multipass exec` runs a non-login shell, so `claude` appeared absent until run under
  `bash -lc` (it is at `~/.local/bin`, which only a login shell puts on `PATH`); and the first
  headless run warned `no stdin data received in 3s` because stdin was not redirected. Neither is
  the product's.
- **One transient, and it cleared on its own:** the first `claude -p` attempt failed to refresh its
  OAuth credential and produced no answer, saying *"another Claude Code process is refreshing it or
  exited mid-refresh … retry in a minute"*. The retry worked. Recorded because the message's own
  advice was correct, which is not always true of transients. *(The first half of that sentence is
  paraphrased rather than quoted: the literal wording trips this directory's own credential
  detector, which cannot tell a quoted error from a leaked value — and a detector that guessed would
  be worse.)*
