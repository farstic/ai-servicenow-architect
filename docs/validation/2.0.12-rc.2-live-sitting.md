## Observer notes

- **Both runs co-fired.** T-29's F3 also adopted FSO and CSM with `Skill` and reconciled them in one Envelope
  file. T-30 is the case that judges the co-fire; T-29 is not judged on it.
- **T-29's stage list was cut by the query's row limit, not the read budget.** One `sys_choice` read covered
  state, stage and status over three tables (read 3 of 7), and seven of the eight reads were used. The Envelope
  cited the list as partial, which is honest. Reading such a list to its end is a follow-up, below.
- **T-30's bare name is a link target outside the bundle.** The FSO Envelope cites Advanced Work Assignment as
  baseline through `markdown/financial-services-operations/configure-assignment-rules-fso-applications.md`. That
  page links AWA to `conversational-interfaces/awa-overview.md` upstream, and the bundled corpus carries no
  `conversational-interfaces` area, so the page is not in the corpus, as the Envelope says.
- **C122's update set was set to Ignore before the removals.** The owner set `demo-pdi-c122` to Ignore in the UI
  at 20:03:08, then removed the step and the test at about 20:06. The set's preview still lists the two
  INSERT_OR_UPDATE rows, for objects that no longer exist, and no delete. That is consistent with an ignored set
  capturing nothing; the bundled corpus does not describe the Ignore state's capture. The procedure sets Ignore
  last, after the removals.
- **The capture preference changed id between W1 and the teardown.** W1's `snow_us_capture_target_set` updated
  one `sys_update_set` preference, and the teardown's call reported another; only the second exists now. The tool
  never deletes a preference: it updates the one it finds, or creates one, and its `action` says which
  (`packages/snowarch/src/tools/updateset.ts`). So the first was removed between the two calls, outside the tool;
  the Ignore in the UI is the one action recorded between them.
- **"Default" names two update sets on this instance:** the global one, created by the system, and a scoped
  app's. The capture target before W1 was not read, so the teardown chose the global one, and whether that was
  the target before W1 is not known. The C95 and C122 procedures now read it first, as R0.
