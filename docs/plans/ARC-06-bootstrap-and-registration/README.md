# ARC-06 — Bootstrap and MCP registration

Status: **ARC COMPLETE 2026-09-10** · **acceptance closed 2026-09-13 (ARC-06 acceptance PR) — four of ARC-06-S08's criteria amended: they predate ARC-08-S05 and were never revisited** · **S01–S14 merged (14 of 14) — entry gate ADR-0006 Accepted 2026-09-08, satisfied** · Depends on: ARC-01, ARC-03 (B02), ARC-04 (committed `dist/`, unconfigured mode), ARC-05 (B05 contract check, permission block); ARC-00 S-01/S-03/S-05/S-08/S-09/S-15/S-16/S-20 and — entry condition for S01 (D-06 hedge) — the S-14a–g conclusion recorded in ADR-0006 ("monorepo path confirmed"; ARC-00-S12/S14) · Blocks: ARC-07 (B06 slot), ARC-08, ARC-09, ARC-10

## Goal

Deliver the "install in one go" promise: a committed, secret-free `.mcp.json` and `.claude/settings.json` that make `git clone` the registration; a resumable, step-numbered bootstrap that completes **design-only mode with no Node.js** and live mode with one uninterrupted run; and a Claude-first recipe for users who start `claude` in an empty folder and point it at the repository.

## Why it exists

Closes P-01 (two clones + hand-edited `~/.claude.json` with a plaintext password, absolute-path keyed), P-02 (four unstated steps, three contradictory guides), P-17 (the reference install fails its own doctor), P-34 (credential copies in `~/.claude.json`, argv exposure, `.bak-*` files), P-40 (no native Windows path), and the `~/.claude.json`-parsing half of P-16. It replaces `scripts/setup.sh` (1,022 lines of bash keyed on local scope) with a design where nothing is registered imperatively (`00` §5, §9).

## Scope

**In:** `.mcp.json`; `.claude/settings.json` (env, SessionStart hook, permission block from ARC-05); `bootstrap.sh`, `bootstrap.ps1`, `bootstrap.cmd`; `snowarch` / `snowarch.cmd` launchers; `tools/snowarch/bin/snowarch.mjs` with `bootstrap`, `mode`, `version`; steps B00–B09 (`01` §4.2) with `.local/bootstrap-state.json` and per-step input hashes; design-mode toggles; `docs/INSTALL.md` = README body; the Claude-first recipe; `--yes`, `--mode`, `--docs`, `--from`, `--reset`, `--instance-file` flags; the `mode live --register local|user` fallback.
**Out:** the wizard UX of B06 (ARC-07; this ARC calls it), the doctor's check bodies (ARC-08; this ARC calls `--quick` and B08's handshake), upgrade (ARC-09).

## Deliverables

- `.mcp.json` and `.claude/settings.json` exactly as in `01` §5 (permission block generated by ARC-05); a test asserting every `${…}` placeholder carries `:-` and no credential-shaped key exists.
- Launchers: `bootstrap.sh` (bash 3.2-clean; does B00 git/claude checks, B01, B02, B07-design, B09 without Node; execs the Node CLI when Node ≥ 20 is present), `bootstrap.ps1` (same, PowerShell 5.1), `bootstrap.cmd` (`powershell -NoProfile -ExecutionPolicy Bypass -File "%~dp0bootstrap.ps1" %*`), `snowarch` / `snowarch.cmd`.
- `tools/snowarch/lib/steps/B00…B09.mjs`, `lib/state.mjs` (state file: step status, inputs hash, timestamps; never secrets), `lib/mcp-handshake.mjs` (spawn `dist/server.js`, `initialize`, `tools/list`, compare to contract).
- Design-mode toggle writer: `.claude/settings.local.json` merge (never overwrite user keys) with `disabledMcpjsonServers: ["servicenow"]` (design) or `enabledMcpjsonServers: ["servicenow"]` (live), plus `disableAllHooks: true` when Node is absent (S-05 fallback).
- `docs/INSTALL.md` (also the README body): prerequisites table, Path A (with the one-line clone + bootstrap form), Path B, the two dialogs, the Mode line, "what to do if" (links to the generated troubleshooting catalogue), attribution line; a "start `claude` at the checkout root" note — Claude Code reads `.claude/settings.json` and `.mcp.json` from the session's primary working directory (`docs:settings`), so a session started inside `clients/<name>/` loads neither; engagement folders are paths within the checkout, or one checkout per engagement; an "Uninstall" section — delete the checkout (it holds the only credential copy, in `.local/`) and, if used, `~/.config/snowarch/`; nothing was registered in `~/.claude.json`, only Claude Code's own trust/approval record for the folder remains.
- Claude-first recipe text (one paste-able sentence) plus the non-empty-folder clone sequence documented in `docs/INSTALL.md`.
- CI job running `./bootstrap.sh --mode design --yes` (and `.\bootstrap.cmd --mode design --yes` on Windows) on a clean runner, then `./snowarch doctor --json` expecting 0 FAIL.

## Risks

> **Amendment 2026-09-07 (from `03` §F S-14g).** The bootstrap runs `npm ci --omit=dev --ignore-scripts` itself, records wall time, and **asserts completeness** — every non-dev package in `package-lock.json` has its directory under `node_modules` — before declaring the live path ready; a partial tree (slow link, interrupted download) is a FAIL with the remedy "re-run the bootstrap", never a success. Same assertion in the doctor.

> **Amendment 2026-09-07 (from `03` §F S-01 CONFIRMED).** On 2.1.258 the live path shows the workspace-trust dialog only (pre-seeded `enabledMcpjsonServers` is applied at trust time) and the design-only path shows the trust dialog only (`servicenow` is absent from `/mcp`, not "disabled"). INSTALL.md quotes the trust dialog verbatim — including the "⚠ This folder pre-approves N tool permissions in .claude/settings.json … These will apply without asking" line — and the fallback: "if you see 'New MCP server found in this project: servicenow', choose 'Use this MCP server'". The 2.1.214 row is pending; do not promise a count below what each version's row records.

> **Amendment 2026-09-07 (from `03` §F S-05 / S-20 / sitting).** (1) S-05 fallback is option 2: the committed `.claude/settings.json` ships **without** the SessionStart hook; the bootstrap writes the hook into `.claude/settings.local.json` only when Node ≥ 20 is present (never `disableAllHooks`, which would silence the user's own hooks). (2) `${VAR:-}` forwarding of proxy/CA variables in `.mcp.json` is not needed on macOS (the server inherits the launching shell); keep it only as a Windows contingency pending S-03/S-20 Windows. (3) The "what you will see" text is permission-mode- and version-dependent (auto mode is the default on ≥ 2.1.263 and was observed on 2.1.258 too): state the trust dialog, then "in auto mode Claude will run the bootstrap checks without asking; in default mode you will see one approval per command not in the allow list".

> **Amendment 2026-09-06 (from `03` §F S-01 partial).** `enabledMcpjsonServers` pre-seeding is NOT honoured before the workspace is trusted (verified on 2.1.214 and 2.1.258); `disabledMcpjsonServers` is. Consequences: the design-only path stays dialog-free beyond the trust dialog; the live path must budget the trust dialog **plus** one MCP approval unless the owner's post-trust run (ARC-00-S04) shows otherwise. The bootstrap's B09 "Next:" line and INSTALL.md state the count the spike recorded — never fewer.

- S-01 fails → one approval click remains; the summary line already tells the user to expect it.
- S-03 fails on Windows → per-machine resolved paths written to `settings.local.json` and a generated local `.mcp.json` override (fallback in `03`).
- Users run the launcher from a subfolder → B00 detects "not at repo root" and prints `cd`.
